# ML 파이프라인 QA 시스템 (가제) — 흡연 여부 예측 파이프라인

> ①②③ 핵심 기능은 다 만들어졌고 실제 데이터로 검증도 끝났습니다. 다만
> "완성된 프로덕션 파이프라인"은 아닙니다 — 예를 들어 드리프트 체크는
> 아직 학습/추론 파이프라인에 자동으로 안 묶여 있어요 (이유는 아래·
> `DECISIONS.md`). 이 README는 지금까지 정한 것까지만 반영한 스냅샷이고,
> 설계 결정과 그 이유는 [`DECISIONS.md`](./DECISIONS.md)에 있습니다.

## 이 프로젝트가 검증하려는 것

"배포 가능한 ML 파이프라인이라면 QA 관점에서 최소 뭘 갖춰야 하는가"를
직접 설계해보는 프로젝트입니다. 이전에 진행한 [생체 신호 기반 흡연 여부
비교 분석](README.md)에서 쓴 것과 같은 건강검진 데이터를
소재로 삼아, 아래 세 단계를 하나의 파이프라인으로 엮습니다.

```
[신규 데이터] → ① 데이터 품질 검증 게이트 → ② 흡연 여부 예측 모델
                                                    │
                                                    ▼
                                    ③ 모델 버전 비교(A/B) 시 통계 오류 감사
```

1. **데이터 품질 검증 게이트** — 새 데이터가 모델에 들어가기 전에 스키마·분포·
   도메인 규칙을 통과하는지 확인.
2. **흡연 여부 예측 모델** — 검증을 통과한 데이터로 학습·추론.
3. **모델 버전 비교 감사기** — 모델을 새 버전으로 교체할 때, 그 비교 자체가
   통계적으로 유효한지(McNemar 검정, 표본 수) 점검.

## 진행 상황

- [x] ① 데이터 품질 검증 게이트
  - [x] 스키마/타입 체크 (Pandera)
  - [x] 도메인 규칙 (수축기>이완기, 키·체중 기반 BMI 현실성)
  - [x] 통계적 분포 이동 감지 (PSI 주력 + KS-test 보조)
- [x] ② 예측 모델 — HistGradientBoostingClassifier
  - [x] 스키마·도메인 규칙 게이트와 실제 연결 (`filter_to_valid_rows`로 통과한
        데이터만 학습에 사용 — `scripts/train_model.py`)
  - [ ] 드리프트 체크는 아직 이 파이프라인에 안 묶임 (학습 시점 vs 추론
        시점 도구라 의도적으로 분리 — `DECISIONS.md` 참고)
- [x] ③ 버전 비교 감사기 — McNemar 검정으로 v1 vs v2(피처 추가) 비교

## 지금 되는 것

```bash
pip install -e ".[dev]"
pytest tests/ -v                        # 38개 테스트

# data/train_dataset.csv 필요 (data/README.md 참고)
python3 scripts/train_model.py              # ①게이트 → ②모델 학습
python3 scripts/compare_versions.py         # ②v1 vs v2 → ③McNemar 감사
python3 scripts/demo_drift_smoker_vs_nonsmoker.py
```

`compare_versions.py` 실제 실행 결과 — v2(WHtR 추가)가 정말 도움이
됐는지 감사한 것:

```
v1: Accuracy 0.7526  ROC-AUC 0.836
v2: Accuracy 0.7530  ROC-AUC 0.834   (+0.0004, AUC는 오히려 소폭 하락)

McNemar 검정: statistic=0.0119, p=0.9132
➖ 결론: 통계적으로 유의한 차이가 없습니다.
```

WHtR을 추가해도 실질적 개선은 없었습니다 — 감사기가 "이 개선은
숫자상 차이일 뿐 통계적으로는 근거가 없다"를 정확히 잡아낸 사례입니다.
자세한 내용은 `DECISIONS.md`의 "③버전 비교" 항목 참고.

## 남은 일 (다음에 이어서 한다면)

- 드리프트 체크를 추론 시점 파이프라인에 실제로 연결 (지금은 도구만
  있고 자동으로 도는 곳이 없음 — 기준 데이터를 어디에 저장할지부터
  정해야 함)
- v2가 "유의한 차이 없음"으로 나왔으니, 실제로 다른 후보(로지스틱
  회귀, 하이퍼파라미터 튜닝 등)로 버전 비교 감사기를 한 번 더 테스트
  해보면 좋을 것 같음 — 지금은 "차이 없음"만 확인했지 "진짜 차이가
  있을 때 제대로 잡아내는가"는 합성 데이터 테스트로만 확인함
- CI(GitHub Actions 등)에 `pytest` 자동 실행 연결
- 성별 데이터 부재 문제 — 드리프트 체크에서 `height(cm)`가 1위로
  나온 게 그 증거라는 걸 이번에 확인했으니, 이 한계를 어떻게 다룰지
  (다른 데이터 소스 병합 등) 고민해볼 만함

## 왜 이 소재인가

같은 데이터셋으로 이전에 EDA·시각화·통계 검증까지 해봤기 때문에, 이번엔
"분석"이 아니라 "그 분석 결과를 실제로 신뢰할 수 있게 만드는 장치"에
집중할 수 있습니다.
